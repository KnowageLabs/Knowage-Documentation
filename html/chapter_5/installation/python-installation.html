Python Engine

Use the Python package corresponding to 9.1.0 and configure its service URL and authentication consistently with the Java applications. Test a Python dataset, function and widget as applicable after installing the required libraries in the selected environments.

These functionalities use a Python standalone webservice, which allows to submit widgets and datasets scripts and get result from a Python environment already installed on the machine where the webservice runs. For this reason, Python environments need to be installed and configured on the same machine of Knowage server or even on a remote one, and the Python webservice has to be running inside that same environment. Install the interpreter and dependency set qualified for the service package. The tagged package metadata declares Python >=3.7, but this is not a compatibility guarantee for all later Python releases. Its dependency file still pins Flask 1.1.4 and pandas 1.3.5. The public base-image source uses Python 3.8, which reached upstream end of life on 7 October 2024. For a new deployment, obtain a maintained, qualified service build. See Requirements for the verified baseline and its limits.

Install knowage-python webservice

Obtain the service archive or image associated with your 9.1.0 distribution. Do not assume the PyPI package version is 9.1.0: the tagged source’s setup.py declares package version 1.1. Use an explicitly approved artifact rather than installing the latest unversioned package.

For a source deployment, the release source is under Knowage-Python/ in the v9.1.0 tree. In the qualified isolated Python environment, install the supplied dependency file and check the resulting environment:

python -m pip install -r /path/to/Knowage-Python/requirements.txt
python -m pip check

Retain the dependency versions supplied with the package. Install additional script libraries and the production WSGI server from the deployment’s qualified dependency manifest.

For the tagged src/ service layout used below, run the service with <KNOWAGE_PYTHON_HOME>/src as its working directory. app.utilities.configs.HMACKEY_FILE defaults to the relative path hmackey. Place that file in this working directory, readable by the service account, and set it to the same HMAC key used by the Java applications. A packaged service with a different layout may provide its own configuration; follow that package’s instructions.

Run knowage-python webservice

Once you have installed all the requirements, you need to get the python-webservice running. The Python service for KNOWAGE is a Flask application: please take a look at the official documentation. In order to do so, you should rely on a WSGI Server.

On Linux with Gunicorn

If you are working on a Linux environment, take a look at Gunicorn.

The entry point for the application is <KNOWAGE_PYTHON_HOME>/src/knowage-python.py and the default port is 5000.

Use the Gunicorn version and worker dependencies supplied with your qualified service build. The following configuration illustrates service startup; size the worker count and timeouts for the scripts you actually run.

Important

Webservice permissions

The knowage-python webservice must have the OS rights to read/write in its own folders.

Following you can find an example that shows you how to run knowage-python with gunicorn. First you need to create a configuration file called gunicorn.conf.py and place it under <KNOWAGE_PYTHON_HOME>/src folder.

import multiprocessing
bind = "0.0.0.0:5000"
workers = multiprocessing.cpu_count() * 2 + 1
timeout = 30
keepalive = 2
# Run as the dedicated service account; set user/group if required.
loglevel = 'info'
accesslog = '-'
errorlog = '-'
access_log_format = '%(h)s %(l)s %(u)s %(t)s "%(r)s" %(s)s %(b)s "%(f)s" "%(a)s"'

Then start the service from <KNOWAGE_PYTHON_HOME>/src, with the qualified Python environment active.

gunicorn -c file:gunicorn.conf.py knowage-python:application

You can now create a service to start/stop Gunicorn: see your operating system documentation for that.

On Windows with Waitress

Use the Waitress version supplied with the qualified Windows service build. See Waitress.

Create a waitress_server.py in <KNOWAGE_PYTHON_HOME>/src folder with the following content:

import multiprocessing
from waitress import serve
import importlib

knowage = importlib.import_module("knowage-python")

serve(knowage.application,
    channel_timeout=30,
    host='0.0.0.0',
    port=5000,
    threads=multiprocessing.cpu_count() * 2 + 1
)

Run from <KNOWAGE_PYTHON_HOME>/src, with the qualified environment active:

python waitress_server.py

Configure Knowage to enable Python/R functionalities

From the Knowage interface you can now enable the Python/R functionalities.

Go to the Roles management section, in the Authorizations tab under Widgets check the Edit Python Scripts option. Now you will be able to see the Python and R Dataset and Widget among the list of available ones.

Go to the Configuration management section, and create new variables of category PYTHON_CONFIGURATION and R_CONFIGURATION. For the label you can use python.default.environment.url. The value of this variables will specify the addresses of the Python and R webservices (es. python.webservice.address.com/domain). Now you will be able to see the addresses of the so configured environments when creating a Dataset or a Widget.
